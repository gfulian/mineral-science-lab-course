Linux essentials

The computational laboratories use Linux in two places:

  • the terminal inside your GitHub Codespace;
  • the CluMiner cluster.

There are many commands and utilities in a Linux distribution; however, for this course, a small set of shell commands is enough to move between directories, inspect files, prepare calculations and check results.

The examples below use generic filenames. Replace them with the files used in the current laboratory.

The shell and the current directory

A terminal prompt represents a shell waiting for a command.

The first useful question is often:

pwd

pwd means print working directory. It shows where you currently are.

For example:

/home/yourname/mineral-science/lab02

Linux paths use / as the directory separator.

List files

ls

lists the contents of the current directory.

Useful variants are:

ls -l

for a detailed listing, and:

ls -lh

for a detailed listing with human-readable file sizes.

To include hidden files:

ls -la

Hidden filenames begin with a dot, for example:

.git

Move between directories

Enter a directory:

cd lab02

Move one level upward:

cd ..

Return to your home directory:

cd

or:

cd ~

A path beginning with / is an absolute path:

/home/yourname/mineral-science/lab02

A path such as:

outputs/mgo_shrink4.out

is relative to the current directory.

TipWhen a file cannot be found

Check both:

pwd
ls

before changing anything. Many “missing file” problems are simply “wrong directory” problems.

Create directories

Create one directory:

mkdir lab03

Create a hierarchy if necessary:

mkdir -p ~/mineral-science/lab03

For the course, a simple structure such as

~/mineral-science/
├── lab02/
├── lab03/
└── lab04/

is sufficient on CluMiner.

Copy files

Copy a file:

cp mgo_shrink2.d12 mgo_shrink3.d12

This is useful when preparing a convergence series.

Copy a file into another directory:

cp mgo_shrink3.d12 inputs/

Always inspect the copied file before submitting it.

Rename or move files

mv oldname.d12 newname.d12

or:

mv mgo_shrink3.d12 inputs/

mv both renames and moves files.

Remove files: use with care

Remove one file:

rm unwanted.out

Linux normally does not move files to a recycle bin.

Warningrm is destructive

Do not use commands such as:

rm -rf *

in course directories.

If you are unsure, stop and inspect the directory with pwd and ls first.

Read a text file

For short files:

cat mgo_shrink3.d12

For longer files:

less mgo_shrink3.out

Inside less:

Key Action
Space next page
b previous page
/text search forward
n next match
q quit

For the beginning or end of a file:

head mgo_shrink3.out
tail mgo_shrink3.out

To follow the last lines of a file that is still growing:

tail -f filename

Exit tail -f with Ctrl+C.

Search for text

grep searches lines containing a pattern:

grep "SCF ENDED" mgo_shrink4.out

or:

grep "SHRINK" mgo_shrink4.d12

Case-insensitive search:

grep -i "termination" mgo_shrink4.out

The laboratories normally use Python/Quantas to extract scientific results. grep is mainly a quick way to inspect an output manually.

Wildcards

The shell can match groups of filenames.

For example:

ls *.out

lists all .out files in the current directory.

ls mgo_shrink*.out

lists all outputs whose name begins with mgo_shrink.

Wildcards are useful, but be particularly careful when combining them with destructive commands such as rm.

Command history

Press the up arrow to recover previous commands.

You can also display recent commands with:

history

This is useful when the same cluminer-crystal command must be repeated with a different input filename.

Interrupt a foreground command

If a terminal command is running interactively and you need to interrupt it:

Ctrl+C

This is different from cancelling a submitted Slurm job. A CRYSTAL job submitted through cluminer-crystal runs under the cluster scheduler, not as a normal foreground terminal process.

Check a file type and line endings

The command:

file mgo_shrink3.d12

can reveal whether a transferred text file contains Windows-style CRLF line endings.

For small edits on CluMiner, the course recommends Vim. See Vim — Quick reference for editing and converting files to Unix line endings.

A typical Mineral Science shell workflow

mkdir -p ~/your-surname/mineral-science/lab02
cd ~/your-surname/mineral-science/lab02

ls
cp mgo_shrink2.d12 mgo_shrink3.d12
vim mgo_shrink3.d12
cat mgo_shrink3.d12

cluminer-crystal mgo_shrink3.d12 --cores-per-node 2 --threads 2

The important part is not memorizing the commands. It is maintaining a clear relationship between:

where you are
what file you are editing
what calculation you are submitting
where the resulting output will appear

Built-in documentation

Many Linux commands provide a manual page:

man cp
man grep
man less

Exit a manual page with q.
